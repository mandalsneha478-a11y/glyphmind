# GLYPHMIND

**Spatial RAG for text-native art.**
Three subsystems, one retrieval engine, zero API keys.

```
 ____ _    _   _ ____  _   _ __  __ ___ _   _ ____
/ ___| |  | | | |  _ \| | | |  \/  |_ _| \ | |  _ \
| |_| | |__|  _  |  __/|  _  | |  | || || |\  | |_| |
\____|_____|_| |_|_|   |_| |_|_|  |_|___|_| \_|____/
```

| # | Section | What it does |
|---|---------|--------------|
| 01 | **Blueprint Reader** | Index any ASCII diagram, network topology, floor plan or state machine, then ask it questions it can *prove* — connectivity, routing, containment, relative position — with every claim cited back to the exact rectangle of the drawing it came from. |
| 02 | **ASCII / ANSI Architect** | Describe *anything*. The prompt is decomposed into separate queries, each searched against a knowledge base of scene recipes; winners are assigned to depth layers (sky · horizon · subject · ground · foreground · weather) and executed by procedural generators that synthesise detail at any canvas size. |
| 03 | **Concrete Poetry** | Give it an emotion or your own poem; it retrieves a structural formula for the figure, a flow strategy from a real calligram, and thematic lexical clusters, then packs the text into the silhouette scanline by scanline. |

Sections 01 and 02 are the two halves of the same ASCII problem — **reading** text-native geometry and **writing** it. Section 03 applies the identical retrieval machinery to a different art form.

## Run it

**Everything, one command:**

```bash
python run.py
```

Then open **http://127.0.0.1:8000**

That builds the React UI if needed and serves the whole app — API and front end — from a single port.

<details>
<summary><b>Other ways to run it</b></summary>

```bash
python run.py --dev        # backend :8000 + Vite hot-reload UI on :5173
python run.py --check      # full self-test, no server, prints timings
python run.py --port 9000  # serve somewhere else
python run.py --no-build   # API only, skip the UI build

./run.sh                   # macOS / Linux wrapper
run.bat                    # Windows wrapper
```

Manual, if you prefer the two processes separate:

```bash
# terminal 1
cd backend && uvicorn app:app --reload --port 8000

# terminal 2
cd frontend && npm install && npm run dev      # → http://localhost:5173
```

</details>

### Dependencies

```bash
pip install -r requirements.txt     # Python
cd frontend && npm install          # Node (run.py does this for you)
```

The only heavy entry is the pre-built local embedding model (`all-MiniLM-L6-v2`, ~90 MB, downloaded once then fully offline). If it is unavailable the system transparently falls back to a built-in hashed n-gram encoder and keeps working — nothing breaks, nothing blocks.

Want an instant cold start with no download at all:

```bash
GLYPHMIND_OFFLINE=1 python run.py
```

### Optional: local LLM narration

If an [Ollama](https://ollama.com) daemon happens to be running, GLYPHMIND will hand it the **already-computed facts** and ask it only to rephrase them. It is a narration layer, never a reasoning layer — the grounded answer is complete without it.

```bash
ollama serve & ollama pull llama3.2
python run.py
```

No Ollama, no problem. No cloud keys are used anywhere in this project.

## Why this is not an ordinary RAG demo

Standard RAG flattens a document into a token stream. Do that to a diagram and you have destroyed the only signal that mattered. A box whose label sits on row 7 and whose outbound arrow sits on row 9 becomes two unrelated chunks, and the fact that they were *vertically adjacent* — the entire meaning of the drawing — is annihilated.

GLYPHMIND never flattens.

### Where the RAG actually is

Every section names its corpus and its queries in the UI, and streams the real retrieval trace beside the output.

| Section | Corpus searched | What the retrieved records decide |
|---|---|---|
| **01 Reader** | the 2-D chunk index of the active drawing + its recovered graph | which rectangles of the picture answer the question, and which graph operations to run |
| **02 Architect** | ~45 scene recipes, 21 shape formulas, palettes, frames, typefaces | which elements exist, in which depth layer, with what parameters, in what colours, in which typeface |
| **03 Poetry** | 21 shape formulas, 8 calligram exemplars, 12 lexical clusters | the silhouette, the flow strategy, and the vocabulary the poem may use |

Nothing is sampled from a model. Every element of every output traces back to a retrieved record with a score, and the interface prints that score.

- **2-D grid-matrix chunking** at three simultaneous scales, plus gap-tolerant connected regions, row/column bands, and one chunk per parsed node and edge. Every chunk carries its bounding box.
- **Dual-stream embeddings.** A pre-trained sentence encoder handles meaning; a hand-engineered 72-dimensional geometric descriptor handles form. They are L2-normalised independently, then concatenated, so the contribution of each stream to any score is exactly recoverable — and the UI shows it live.
- **Computer vision on a character matrix.** A rectangle scanner, a wire segmenter that bridges inline edge labels, contextual arrowhead disambiguation (`v` is a letter in *Svc* and an arrowhead under a pipe), and co-reference for repeated FSM states.
- **Four retrievers, fused.** Dense cosine, BM25, a spatial-only scan against a prior synthesised from locative language, and symbolic graph expansion — merged with reciprocal rank fusion under intent-dependent weights.
- **Answers are derived, not generated.** Structural questions are computed over a `networkx` graph. The composer renders facts into prose deterministically. It cannot hallucinate because it has no generative freedom.
- **Art is retrieved and solved, not sampled.** The Architect decomposes a prompt into up to nine queries, max-pools the scores, assigns winners to depth layers under mutual-exclusion rules, and runs parametric generators — fractal ridges, window-lit skylines, perspective-compressed oceans, computed reflections. An unmatched noun falls through a three-tier ladder (scene recipe → shape formula → monumental typography) so *any* prompt renders something deliberate.

The full argument, with the algorithms, is in **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.

## The interface

Every heavy endpoint has a **Server-Sent Events twin** that streams each pipeline stage as it completes, with its real cost in milliseconds. The right-hand **Observatory** panel renders that live: which intent fired, what spatial prior was synthesised, what each of the four retrievers returned and at what rank, how fusion weighted them, which graph operations produced the facts.

In the Reader, hovering any retrieved chunk lights up **the region of the picture it came from**. Retrieval stops being a claim and becomes something you can watch.

## API

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | readiness, encoder, dimensions, corpus sizes, LLM status |
| `GET /api/catalog` | every retrievable asset — shapes, palettes, frames, fonts, strategies |
| `POST /api/ingest` · `/api/ingest/stream` | index a drawing (streaming reports each stage) |
| `POST /api/query` · `/api/query/stream` | ask a question; streaming emits the full retrieval trace |
| `POST /api/architect` · `/api/architect/stream` | compose ASCII/ANSI art |
| `POST /api/poetry` · `/api/poetry/stream` | shape a concrete poem |
| `GET /docs` | interactive OpenAPI explorer |

```bash
# render a scene and print the plain-text art
curl -s localhost:8000/api/architect \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"a lighthouse in a storm over the sea","width":110,"height":36}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['plain'])"

# ...or inspect what retrieval decided, and why
curl -s localhost:8000/api/architect \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"a lighthouse in a storm over the sea"}' \
  | python -c "
import sys,json
for p in json.load(sys.stdin)['scene']['picks']:
    print(f\"{p['layer']:<8} {p['name']:<22} {p['score']:<8} {p['reason']}\")"
```

## Verifying it works

```bash
python run.py --check
```

Indexes all five seed diagrams, runs ten questions across every intent class, synthesises seven scenes — including two prompts deliberately chosen to have *no* matching recipe, to exercise the fallback ladder — and shapes three poems.

Each scene is asserted to be rectangular, free of out-of-slot writes, to carry at least three depth layers, and to land inside a sane ink-density band: too sparse reads as empty, too dense reads as a solid block, and both are failures.

Typical numbers on a laptop: **~180 ms** to index a diagram end to end, **1–4 ms** per retrieval, **~25 ms** per scene, **~10 ms** per poem.
